1.4 
Approach 
The approach chosen to respond to A/E/C community comments and 
feedback entailed reviewing their concerns and recommendations. If the 
comment was from a purely personal preference standpoint, it was 
disregarded. If the comment proposed an object opportunity for 
improvement, a workaround was determined on how to best resolve the 
issue while still maintaining the intent of industry standards. A Frequently 
Asked Questions (FAQ) page was established to document the interim 
solutions. This document updates the A/E/C Standards to incorporate 
those solutions. 
The intent of this document is to embrace the National CAD Standard 
while providing more guidance and clarifying areas of misunderstanding. 
This document will not cover every circumstance encountered in drawing 
production. There may be specialized instances where it will be up to the 
site to develop internal best practices. 
1.5 
Scope 
This manual provides guidance and procedures for preparing CAD 
products within the DoD. Chapters 2–5 of this manual address topics such 
as presentation graphics, level/layer assignments, digital file naming, and 
standard symbology. Appendix A contains tables on model file level/layer 
names. 
1.6 
Target Systems 
This standard does not target any specific CAD system or software but 
does specifically target CAD workflows. To ensure successful translations 
among CAD applications, certain system-specific characteristics were 
considered and the standard adjusted accordingly. During the preparation 
of the standard, certain baseline decisions were made: 
• The standard must be applicable to the latest release of commercially 
available CAD packages. AutoCAD and MicroStation were chosen 
based on their prevalence within DoD.

1.7 
Design Applications and Other Applications 
Numerous design applications have been developed to run on top of or 
alongside basic CAD engines. These applications can be used by designers 
to generate graphics inside CAD files.  
Document management systems that contain attributes or metadata for 
individual files and have such features as attribute exchange are becoming 
standard tools for management of digital files. Use of these systems to 
store searchable metadata for files is encouraged. 
1.8 
Coordination with Design Agent 
With all the complexity and options currently available, it becomes vitally 
important to coordinate the fundamental aspects of design. Each project 
should have an initial discussion and agreement between the designer and 
customer on topics such as: design software, review software, output file 
format(s), and so on.  
1.9 
Additions/Revisions 
This Standard is intended to be neither static nor all inclusive. Suggestions 
for improvements are strongly encouraged so that subsequent updates will 
reflect the input and needs of the users. 
Recommendations or suggested additions should be sent by email to 
CADBIM@usace.army.mil.

2.1 
CAD File settings 
2.1.1 Available Design Area 
The two most extensively used CAD applications within the DoD, 
AutoCAD and MicroStation, both provide for a design area with nearly 
infinite range in each positive and negative axis (x,y,z). 
2.1.2 File Accuracy (Units) 
CAD systems allow the designer to work in real-world units. The most 
common units are feet:inches, survey feet:hundredths of survey feet (or 
thousandths), and meters:millimeters. 
2.1.3 International Feet versus Survey Feet 
Many sites must contend with the initial question as to whether a 
particular project is designed using international feet or survey feet. In 
some states, it is specified by statute that units of measure for grid 
coordinates must be either international feet or survey feet. The two units 
are defined as follows: 
• International feet: 1 ft = 0.3048000 m. 
• US survey feet (SF): 1 SF = 1,200/3,937 m. 
Note: At the time of the revision of this document, the US survey foot is 
scheduled to be deprecated by the National Institute of Standards and 
Technology (NIST) and the National Geodetic Survey (NGS). Be sure to 
check with the issuing agency for required coordinate systems and units.  
Note: If a drawing has already been created using international feet, 
changing the master units to survey feet will not automatically scale all 
elements in the drawing to survey feet. Also, survey feet and 
international feet should not be mixed in similar disciplines due to 
horizontal shifts over large distances. 
2.1.4 Origin (Global Origin) 
Positioned within every digital drawing file is an origin (“global origin” in 
MicroStation and “origin” in AutoCAD). The origin of a drawing file is

2.2 
CAD File Contents 
CAD files contain various types of designs (2D or 3D) used to generate 
construction plans. The contents of these files will vary depending on the 
design authoring software but typically contain the following types of 
areas: 3D modeling, 2D drawing, and/or the 2D sheets (see Sections 2.2.1, 
2.2.2, and 2.2.3). Depending on project requirements, project size, or 
design authoring software, the CAD files for a project may be organized by 
file use (e.g., project, discipline, modeling/drawing/sheet area type, file 
extension, etc.) and contain one or multiple types of areas (Figures 2-1 and 
2-2).  
Note: A MicroStation design file (.dgn) may have multiple modeling 
areas (design models) and multiple drawing areas (drawing models), 
while an AutoCAD design file (.dwg) will have only one modeling area or 
drawing area (model SPACE). Both MicroStation and AutoCAD may 
contain multiple sheet areas (MicroStation:Sheet Models, 
AutoCAD:Layouts/Paper Spaces).

2.2.1 Modeling Area 
The modeling area is where the 3D representation of physical components 
of a design (e.g., terrains, roads, curbs, columns, walls, windows, 
ductwork, piping, etc.) are drawn at full size (see Figure 2-2). Annotation 
is typically used sparingly in the modeling area to avoid text being 
misinterpreted as drawing content in alternate views. 
2.2.2 Drawing Area 
The drawing area is where the 2D graphical representation of physical 
components of a design are drawn at full size along with any annotation 
items (see Figures 2-1 and 2-2). Drawing areas can be generated either by 
placing graphics or by cutting views from modeling areas. Drawing areas 
include items such as plans, sections, elevations, and details. 
2.2.3 Sheet Area 
The sheet area is where views of the modeling areas and/or drawing areas 
are assembled to create a digital representation of the full-size plotted 
sheet. The sheet area contains a reference to the border sheet at 1:1. The 
addition of sheet-specific information (e.g., sheet annotation, symbols, 
sheet notes, etc.) completes the construction of the sheet area (see Figures 
2-1 and 2-2). 
2.3 
CAD File Types 
A CAD file is a container of the areas documented above. The CAD file 
types are model files and sheet files. It is important to name files 
appropriately so that model and sheet files can be easily distinguished. 
2.3.1 Model Files 
Model files contain modeling areas and/or drawing areas. Model files are 
developed or assembled prior to creation of sheet files. The components 
contained within a model file may be referenced by other models. Each 
reference shall have a unique name or logical description describing what is 
being referenced. 
Referencing digital drawing information makes changes readily apparent 
to all design disciplines. This real-time access to the work of others

Note: Never bind/merge external references into the sheet areas since 
that will duplicate linework and increase the amount of work required to 
make future revisions. 
2.3.1.1  Border Sheet Model Files 
Border sheets are drawing areas in model files externally referenced by all 
disciplines to create sheet areas. This model file contains border linework, 
the title block, and project-specific symbols and text. All disciplines shall 
use the same border sheet within a project (for more information on 
border sheets, see the A/E/C Graphics Standard). 
2.3.1.2  Raster References 
Although raster imagery is not accurate, it allows for the reader to relate 
the design linework to real world objects. For interoperability, the most 
common raster file types referenced are TIF, JPG, and PDF. Raster file 
names shall conform to the model file naming convention with a model file 
type of “IG” (e.g., (Project Code)C-IG(User Defined).tif/jpg/pdf). 
Raster File Type uses: 
• GeoReferenced TIF: Best for aerial photographic imagery, maps, and 
drawings where the image is referenced under linework to add clarity. 
• JPG: Best for nonaerial photographic imagery used for depicting 
existing conditions referenced to sheets. 
• PDF: Best for historic drawings used as background images. 
Note: It is suggested that MrSID files are not directly referenced. The 
files are extremely large and unwieldy to manage in a CAD/BIM / civil 
information modeling (CIM) environment. It is recommended that the 
MrSID image be clipped, resampled, and saved as a georeferenced TIF 
file. The smaller file size allows the software to open faster and plot more 
efficiently. 
2.3.2 Sheet Files 
A sheet file is a file that contains a sheet area or multiple sheet areas. A 
sheet file is a ready-to-plot CAD file. Sheet files may also contain drawing

2.4 
CAD File Naming Conventions 
Naming conventions for CAD files allow users to determine the contents of 
a file without opening it. They also provide a convenient and clear 
structure for organizing CAD files within a project directory.  
Spaces are not allowed in any CAD filename. An underscore (_) or 
CamelCase may be used in lieu of a space, or a hyphen (-) may be used as a 
separator. 
2.4.1 Project Code 
The CAD file naming conventions require a Project Code (1 to 20 
characters) at the beginning of the filename. The Project Code shall be 
identified at the start of each project to ensure consistent filenames within 
that project. Some examples of Project Codes include: 
• the official agency project number and 
• the project number defined by the contract issuing agency CAD 
manager for their record system. 
The purpose of a Project Code is to indicate which project a CAD file is 
associated with. 
When deciding on a standard file naming convention, the user might 
consider the use of a special character such as an underscore (_) (as part 
of the 20-character Project Code) at the beginning of the model filename 
so that model files are grouped together.  
When a project includes multiple structures, features, or options, it is 
important to identify each file with the appropriate feature. This should be 
done as a part of the Project Code. For example, a model file for project 
P123 and building 2 could use a Project Code of _P123-Bldg2.

2.4.3 Model File Naming 
There are two different types of model files: modeling area files and 
drawing area files. The primary difference between these two types is that 
modeling areas are typically used to portray 3D and drawing areas are 
used to portray 2D. The NCS’s model file naming convention primarily 
focuses on 2D drawing practices and does not provide guidance for 
modeling area file types.
